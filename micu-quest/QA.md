## 실제 UI 검증

Cloud Chromium 데스크톱 브라우저에서 다음을 직접 실행했습니다.

- 시작 화면, 세 병실 선택, 병실 페이드 진입
- 타이핑 표시, 첫 클릭으로 같은 대사 완성, 다음 클릭으로 다음 대사 진행
- 대사 표시 속도 저장과 반영
- 빈 답 제출 차단, 오답 반응과 흔들림, 힌트
- 화면 키패드의 37.5 입력, 정답 제출, 계산 풀이 펼치기
- 01호실 37.5 → 9, 02호실 10 → 33.33 → 16.67, 03호실 7 → 5.25를 실제 입력
- 병실 완료와 다음 환자 선택, 전체 7개 미션 완료 화면, 3/3 병실 집계
- 농도 0 저장 거부, Norepinephrine 8 mg / 최종 100 mL 저장 후 새로고침 유지
- 변경 농도에서 7.5 mL/hr 정답 처리
- 진행 중 농도 변경 잠금
- 시작 화면 복귀 확인창의 계속하기 / 복귀, 예시 농도 복원

## 모바일 / Safari 범위

Cloud Chromium의 390 × 844 CSS viewport에서 시작, 선택, 병실 대화, 처방/계산 화면을 검사했습니다. 가로 넘침이 없고, 화면 키패드와 제출 동작은 동일한 로직을 사용합니다. 모바일에서는 반복되는 임상 소개를 대화에 두고 계산 화면은 체중·처방 용량·희석 농도 중심으로 압축했습니다.

이 작업 환경에는 실제 iPhone 또는 Safari/WebKit 브라우저가 연결되어 있지 않습니다. **실제 iPhone Safari에서 실행을 검증했다는 의미는 아닙니다.** Safari에서 지원하는 표준 ES modules, dialog, requestAnimationFrame, safe-area와 dvh를 사용하며 외부 라이브러리에 의존하지 않습니다. 효과음과 로컬 저장소 차단은 게임 중단 없이 처리합니다.
