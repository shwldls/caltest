# v3.5.0 배경음·대사음 검증 · 2026-11-02

오리지널 84 BPM 배경음과 글자 표시에 맞춘 대사 합성음을 추가했습니다. Web Audio는 첫 사용자 조작에서 시작하며 상단 소리 끔, 개별 배경음 끔, 개별 대사음 끔, 화면 벗어남에서 해당 재생을 정리합니다.

계산 테스트 8개와 오디오 상태 테스트 5개를 통과했습니다. 오디오 테스트는 자동 재생 방지, 배경음 중복 방지·독립 중단, 공백/문장부호 무음과 발음 빈도 제한, 전체 음소거, 화면 복귀 후 새 컨텍스트 생성, resume 지연 시간 제한, 시작 대기 중 음소거를 검증합니다. 이는 모의 AudioContext 검사이며 기기 스피커 청취 검사는 아닙니다.

Chromium 실제 화면에서 소리 켜기 성공 경로, 배경음·대사음 개별 끄기 저장 후 새로고침 유지, 다시 켜기, 느린 대사→다음→계산→20.0 정답→전체 음소거를 확인했습니다. 게임 출처의 오디오 실행 오류가 관찰되지 않았습니다. 실제 iPhone Safari 또는 홈 화면 웹앱의 청취 여부는 직접 검증하지 못했습니다.

- mg→mcg, 체중, min→hr, units 계산 및 소수 반올림
- 농도 변경에 따른 문제·정답·힌트·풀이 동기화
- 빈 값·0·음수·비수치·과학적 표기 및 잘못된 희석 설정 차단
- 각 병실의 대화→계산→오답→재시도→정답→후속 처방→완료
- 중복 제출 방지, 재도전 시 해당 병실 시도와 힌트 초기화

## 이번 버전에서 직접 플레이한 UI 검증

Cloud Chromium 브라우저에서 실제 화면의 버튼과 입력창을 사용했습니다.

- 시작 화면, 3개 병실 카드, 배경의 침상 선택, 페이드 전환
- 느린 타이핑에서 첫 클릭은 4/4 대사를 그대로 완성하고 다음 클릭은 문제로 이동
- 빈 값 제출 오류, 오답 메시지와 의사 반응, 힌트
- 화면 키패드로 37.5 입력, 정답과 계산 풀이 펼치기
- 01호실 37.50→9, 02호실 10→33.33→16.67, 03호실 7→5.25 전부 직접 제출
- 7개 미션·3/3 병실 전체 완료 및 계산 기록, 다음 참가자 시작 후 진행 초기화
- Norepinephrine 약물량 0 저장 거부
- Norepinephrine 8 mg / 최종 100 mL 저장, 새로고침 후 유지 및 7.5 정답 처리
- 진행 중 희석 농도 잠금, 타이핑 속도 변경, 예시 농도 복원
- 중도 복귀 확인창의 계속하기와 시작 화면 복귀

## 모바일 크기 검사와 한계

같은 Chromium 브라우저의 로컬 iframe 테스트 화면으로 390×844, 320×568, 844×390 CSS viewport를 검사했습니다. 실제 iPhone 또는 터치 하드웨어 에뮬레이션은 아닙니다.

- 390px 화면의 병실·초상화·대화창, 처방·키패드·제출 버튼 배치 확인
- 390px과 320px에서 실제 화면 키패드로 7 및 5.25 입력·삭제·정답 제출
- 두 진정/진통 처방과 병실 완료, 가로 화면에서 다음 환자 선택 및 랜덤 배정
- 각 너비에서 문서의 scrollWidth와 viewport 너비가 같음을 확인
- 작은 화면에서는 세로 스크롤로 다음 버튼과 계산 입력 영역에 접근 가능
- 큰 PC 화면에서는 게임 캔버스 16:9 유지

**실제 iPhone Safari/WebKit 실행은 이 환경에서 검증하지 못했습니다.** iOS용 safe-area, dvh, 16px 이상 설정 입력 글꼴, 터치 기기의 화면 키패드, 선택적 효과음, 저장소 오류 처리를 구현했습니다. iframe 검사 결과를 실제 Safari 테스트로 표현하지 않습니다.

배포는 기존 GitHub Actions의 Flutter 검사/빌드 및 gh-pages 배포 흐름을 사용합니다. 변경 범위는 `micu-quest/`뿐이며 약물계산기의 `lib/`, `web/`, `app_assets/`, 기존 테스트, workflow는 보존합니다.
